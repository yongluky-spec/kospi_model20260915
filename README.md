# KOSPI Market Decision Engine (kospi_model.py)

이 프로그램은 스크린샷에서 보셨던 그 앱입니다. 확인해보니 지금까지 젬미나이가
대화로 만들어냈던 것들과 질적으로 다른, 실제로 잘 설계된 프로그램입니다.

## 이 프로그램이 신뢰할 만한 이유

- **GJR-GARCH(1,1,1)을 실제로 데이터에 적합(fit)시킵니다.** 감마(비대칭계수)가
  미리 정해진 숫자가 아니라 매번 실제 수익률로 추정됩니다.
- **벨만 최적화가 진짜 동적계획법(backward induction)입니다.** 상태공간
  (0/25/50/75/100% 포지션)에 대해 실제로 가치반복을 계산하고, 모든 가정
  (기대수익, 리스크회피계수, 리밸런싱 비용)을 사이드바에서 직접 조절하고
  화면 하단에서 확인할 수 있습니다.
- **"테일러 급수 곡률 분석"에 스스로 한계를 명시합니다.** "실제 주가는 매끄러운
  함수가 아니므로 엄밀한 테일러 급수가 아니라 근사"라고 캡션에 명확히 적혀
  있습니다.
- **신뢰도 보정 필터**가 있어서, 거래량이 부족하거나 변동성이 과열 상태면
  "가짜 이탈 가능성"이라고 스스로 경고합니다. 숫자만 던지지 않고 그 숫자를
  얼마나 믿어야 할지도 같이 알려줍니다.
- 한국 선물 데이터가 무료로 신뢰성 있게 제공되지 않는다는 걸 알고, 아예
  KOSPI200 현물은 KODEX 200 ETF로 대체하고 선물은 참고용으로만 표시하도록
  설계되어 있습니다.

## 이번에 추가로 수정한 것

야후파이낸스가 코스피(^KS11) 데이터를 특정 시점 이후 갱신하지 않는 현상이
실제로 확인되어서, 코스피/코스피200 데이터는 이제 **KRX 원천(pykrx)을 우선
시도**하고, KRX 인증이 실패하면 **네이버 금융 지수 API**, 마지막으로 야후파이낸스를
사용합니다. 화면 상단 캡션에 실제 사용한 소스와 기준일이 표시됩니다.

## 실행 방법

프로젝트 루트에서 항상 저장된 표준 실행 스크립트를 사용합니다. 이 스크립트가
실행 파일 경로, 포트, 외부 접속 주소, 저장 시 자동 갱신 옵션을 고정하므로 VS Code
에이전트·터미널·Codespaces가 서로 다른 앱을 띄우지 않습니다.

```
python -m pip install -r requirements.txt
chmod +x run_streamlit.sh
./run_streamlit.sh
```

앱 주소는 `http://localhost:8505`이며 Codespaces에서는 전달된 8505 포트의 외부
주소를 사용합니다. `kospi_model.py`를 저장하면 `runOnSave`가 자동으로 최신 코드를
다시 실행합니다. `streamlit run kospi_model.py`를 별도로 실행하지 마세요.

## 사이드바에서 조절 가능한 것

- 코스피/코스피200/선물/환율/VIX 티커 (기본값 그대로 쓰시면 됩니다)
- 벨만 최적화 파라미터: 리스크회피계수, 리밸런싱 비용
- 확장형 GJR-GARCH 파라미터: 거래량/괴리 가중치, 상하단 승수
- 분석 기간 (6개월~5년)

## 예측 검증 로그

앱을 실행할 때마다 `prediction_log.jsonl`에 KOSPI 기준일 종가, 다음 거래일
예상 종가/수익률/방향, 권장 포지션 경로를 저장합니다. 다음 실행부터 가장 최근
예측과 오늘 실제 종가를 자동 비교해 종가 오차와 방향 적중 여부를 표시합니다.

로그 저장 위치를 바꾸려면 실행 전에 `KOSPI_PREDICTION_LOG` 환경 변수를 지정합니다.

각 예측 기록에는 방향 점수·신뢰도·시장 국면·헤지 단계와 함께 거래량 비율,
단기 변동성 비율, 원화 5일 변화율, VIX, 매크로 위험 여부가 저장됩니다.
다음 거래일 실행 시 이전 예측의 실제 방향과 적중 여부를 재구성해 화면의
신뢰도 추이 표에 표시합니다. 신뢰도는 확률 보정값이 아니라 현재 점수의 절댓값이므로,
장기적인 신뢰도 평가는 반드시 충분한 표본과 구간별 백테스트로 확인해야 합니다.

## 장 마감 후 사후 평가와 반자동 보정

앱을 장 마감 후 다시 실행하면 새로 수집한 KOSPI 일봉의 종가·고가·저가를 직전 예측과
자동 대조합니다. 방향 적중 여부, 종가 오차, 동적 저항선 도달, 동적 지지선 이탈 결과는
`prediction_log.jsonl`의 이전 예측 레코드에 `evaluation`으로 저장됩니다. 별도의 백그라운드
스케줄러 없이도 다음 거래일 데이터가 갱신된 뒤 `./run_streamlit.sh`를 실행하면 평가됩니다.

최근 평가가 3건 이상이면 화면의 `사후 보정 제안` 영역에서 방향 적중률과 평균 오차를
기준으로 밴드 버퍼 및 리스크회피계수 변경안을 제시합니다. 제안은 자동 적용되지 않으며,
`제안 승인 및 다음 실행부터 적용` 버튼을 눌렀을 때만 `model_adjustments.json`에 저장됩니다.
이 파일의 설정은 밴드 폭과 Bellman 리스크회피계수에만 반영되고 주문을 실행하지 않습니다.

## 반등 vs 국면 전환 및 오버나이트 실행안

대시보드의 반등 시나리오 검증은 직전 5일 수익률이 -2% 이하인 뒤 당일 1% 이상
반등한 과거 사례를 모아, 이후 5영업일 결과를 `기술적 반등 실패`, `국면 전환`,
`추세 진행 중`으로 분류합니다. 각 비율에는 Wilson 95% 신뢰구간과 표본 수를 함께
표시하므로 표본이 적은 확률을 확정적인 예측으로 해석하지 않습니다.

오버나이트 패널은 KOSPI의 실제 종가→다음 시가 갭 분포를 계산하고, 나스닥 종합지수
(`^IXIC`)의 직전 미국장 수익률을 `미국장 상승/하락/혼조`로 나눠 조건부 갭 확률을
표시합니다. 절대 갭 1% 이상 빈도, 현재 미국장 조건, 거래량 부족, 지지선 접촉 여부를
결합해 `현재 유지`, `75% 유지`, `50% 축소 후 개장 확인 재진입` 중 실행안을 제시합니다.
이는 방향을 보장하는 신호가 아니라 갭 노출을 줄이기 위한 규칙이며, 실제 주문 전
상품의 추적오차·증거금·손실 한도를 별도로 확인해야 합니다.

대시보드의 `내일 갭 시나리오와 실전 실행 가이드`는 전체 상승·하락 갭 빈도와 현재
미국장 조건의 조건부 빈도를 함께 보여줍니다. ±1% 이상 갭 빈도가 높고 거래량이
평균보다 부족하면 모델 헤지 레벨을 그대로 유지하지 않고, 장 마감 전 50% 축소 후
개장 갭과 첫 15분 수급을 확인해 재진입하는 시나리오를 우선 안내합니다. 갭 위험이
중간이면 75%만 유지하고, 위험이 낮으면 현재 레벨을 유지하되 손실 한도를 미리
정하도록 표시합니다. 이 값들은 예측 보장이 아니라 과거 관측 통계와 규칙 기반
리스크 관리 결과입니다.

`내일 아침 갭 대응 타임라인`은 이 권장안을 실제 시간대별 행동으로 펼쳐 보여줍니다.
장 마감 전(15:20~15:30)에는 계산된 권장 비중으로 축소하고, 개장 후(09:00~09:15)는
자동 주문 없이 시가와 첫 15분 수급을 관찰하며, 09:15 이후에는 예측 방향과 실제 흐름의
일치 여부에 따라 남은 물량을 재조정합니다. 방향이 반대로 움직일 때는 사용자가 미리
정한 손절 기준을 우선 적용합니다. 앱은 주문을 실행하지 않습니다.

## 시장 에너지 기반 동적 상·하단

동적 에너지 레벨은 다음 공식으로 계산합니다.

`R_dynamic = P_current + (ATR14 × (Volume_actual / Volume_avg) × (1 - |ΔP_5d| / P_current))`

`동적 지지선 = P_current - (R_dynamic - P_current)`입니다. 여기서 `P_current`는
현재 지수, `ATR14`는 기본 변동성 단위, `Volume_actual / Volume_avg`는 거래량
에너지 배수, `(1 - |ΔP_5d| / P_current)`는 모멘텀 저항 계수입니다. 5일 수익률은
소수로 변환해 사용하므로, 예를 들어 -4.73%는 `0.0473`으로 계산합니다.

예를 들어 `P_current=6,717.97`, `ATR14=201.16`, 거래량 배수 `0.64`, 5일 수익률
`-4.73%`라면 거래량 조정 폭은 `201.16 × 0.64 = 128.74`이고, 모멘텀 계수
`1 - 0.0473 = 0.9527`을 포함한 최종 에너지 폭은 약 `122.67`입니다. 따라서
공식 전체를 적용한 동적 저항선은 약 `6,840.64`입니다. `6,846.71`은 모멘텀
계수를 마지막에 적용하지 않은 중간 계산값이므로 최종 공식 결과로 사용하지 않습니다.
거래량 데이터가 없으면 거래량 배수 1.00을 대체하고 화면에 표시합니다.

스윙 저항선(예: `7,194.07`)은 과거 가격 반응으로 찾은 별도 가격대입니다. 가격과
거래량 배수를 서로 나누거나 곱해 새로운 가격을 만들지 않으며, 거래량 배수는 위
공식에서 ATR 변동 폭을 조정하는 무차원 계수로만 사용합니다.

## 반등의 질과 국면 전환 검증

대시보드의 `반등의 질: 가격·거래량·OBV 검증` 패널은 반등이 실제 수급을 동반했는지
확인하는 보조 검증층입니다.

- **가격×거래량 에너지**: 당일 수익률에 거래량을 곱한 값의 절대 크기를 최근 120일
  표본의 백분위로 표시합니다. 단위가 큰 종목과 직접 비교하는 값이 아니라 현재 지수의
  과거 대비 참여 강도를 보는 값입니다.
- **OBV**: 상승일 거래량은 더하고 하락일 거래량은 빼는 누적 지표입니다. 최근 20일
  가격 방향과 OBV 방향이 어긋나면 강세·약세 다이버전스로 표시합니다.
- **ATR×거래량 에너지**: `ATR14 / 현재가 × 거래량 배수`로 계산해 변동성과 참여량이
  동시에 확대되는지 최근 120일 백분위로 확인합니다.

거래량 1.2배 이상, OBV 비감소, 가격×거래량 에너지 50퍼센타일 이상이면 `실제 수급
확인` 가점을 표시합니다. 이 기준은 국면 전환을 확정하는 예측 확률이 아니라 현재
반등의 질을 분류하는 규칙입니다. `반등 형태와 국면 전개 시나리오 검증`의 기술적
반등 실패·국면 전환·추세 진행 중 확률은 과거 조건부 표본의 관측 빈도이며, Wilson
95% 신뢰구간과 표본 수를 함께 확인해야 합니다. 새 지표의 백분위와 OBV 판정은
`prediction_log.jsonl`에도 저장되어 사후 적중률 검토에 사용할 수 있습니다.

과거 각 거래일에서 같은 공식을 다시 계산한 뒤 다음 5영업일에 상단/하단을 실제로
터치한 사례만 모읍니다. 상단 터치 후 마지막 종가가 상단 아래면 저항 거부, 하단
터치 후 마지막 종가가 하단 위면 지지 방어로 라벨링하고, 조건부 확률과 Wilson 95%
신뢰구간을 대시보드와 `prediction_log.jsonl`에 저장합니다. 표본 수와 신뢰구간이
작거나 넓으면 동적 레벨을 매매 신호가 아닌 위험 경계로만 해석해야 합니다.

## 반등 목표가와 분할 청산 가이드

대시보드는 현재가 위의 가장 가까운 스윙 저항 클러스터와 동적 저항선 중 가까운
값을 `1차 목표가`로 제시합니다. 목표가는 확정 예측이 아니라 과거 반응이 확인된
관찰 구간이며, 클러스터 허용오차를 적용한 목표 구간으로 표시합니다.

반등 시 전량 매도 대신 다음 3단계 참고 규칙을 표시합니다.

- 1차 청산: 목표 구간 진입 시 전체 헤지·인버스 물량의 30%를 수익 확정
- 2차 관망·청산: 저항을 거래량 1.5배 이상으로 돌파하면 40%는 보유하고, 돌파가
  실패하면 순차적으로 축소
- 최종 추세 물량: 남은 30%는 방향 점수와 지지선 이탈 여부를 확인한 뒤 정리

이 규칙은 투자 주문을 실행하지 않으며, 거래량이 기준에 못 미치면 저항 거부
가능성을 높게 보고 보수적으로 안내합니다. 목표가에 도달해도 시장 상황, 상품의
추적오차와 손실 한도를 함께 확인해야 합니다.

## 모델-시장 괴리 대응

강한 하방 점수와 당일 반등이 충돌하면 가격·5일 모멘텀·거래량을 추가로 확인해
헤지 단계를 25%p 또는 50%p 낮추는 참고안을 화면에 표시합니다. 외국인·연기금
수급을 직접 측정하는 기능은 아니며, 자동 주문이 아닌 수동 검토용 안내입니다.

현·선물 Basis Z-score가 `|2.0|` 이상이면 선물 데이터를 방향 신호로 직접 합성하지
않고, 현물 방향 점수에 `55%~70%` 할인율을 적용해 괴리로 인한 가짜 신호를 줄입니다.
거래량이 평균 이하이거나 변동성이 과열이면 더 강한 할인율을 사용하며, Basis 데이터가
없을 때는 할인하지 않습니다.

GJR-GARCH를 적합할 수 없으면 EWMA(`λ=0.94`) 변동성을 자동으로 사용해 Bellman
리스크 항과 동적 밴드 계산을 중단하지 않습니다. Taylor 국소 피팅 RMSE가 ATR보다
커지는 경우에는 오차밴드 폭을 최대 3배까지 확대합니다. 방향점수가 혼조 구간에
있을 때는 0~50% 사이의 25%p 레벨 전환을 직전 레벨과 비교해 완화하고, Bellman
리밸런싱 비용도 1.5배 높여 Whipsaw를 줄입니다.

현재 로그 검증 예시로 2026-09-15 예측은 다음 종가 `6,377.09`와 하락 `-3.77%`를
예상했지만, 2026-09-16 실제 종가는 `6,717.97`로 `+1.37%` 상승했습니다. 방향은
불일치했고 종가 상대오차는 약 `+5.35%`였으므로, 이 결과를 성공 사례로 해석하지
않고 이후 보정 로직의 검증 기준으로 기록합니다.

## 비대칭 변동성·동적 밴드 전망

별도 전망 패널에서 테일러 근사 중심 경로와 GJR-GARCH 조건부 변동성 경로를
결합해 향후 5영업일의 동적 상·하단과 오차폭을 표시합니다. 마지막 충격이 음수이면
GJR-GARCH의 γ를 하단 폭에 추가하고, 상승·반등이면 음의 충격에 대한 하단 확대를
적용하지 않습니다. 밴드 폭은 GARCH 가격폭과 ATR14 중 큰 값에 테일러 피팅 오차를
더한 참고값이며, 확정적인 가격 예측은 아닙니다.

### 새로 추가된 4가지 (모두 `advanced_gates.py`에 구현, 실제 데이터 기반)

1. **① ES=F/NQ=F 선물 충돌 게이트**: 선물이 현재 방향점수와 반대로 기준치(기본
   0.5%, 슬라이더 조절 가능) 이상 움직이면, 기존 매크로 게이트와 동일한 '절반
   축소' 규칙을 그대로 적용합니다. "델타 12.0배" 같은 근거 없는 정밀 계수는
   쓰지 않았습니다.

2. **② 대장주(삼성전자·SK하이닉스) 가격 괴리 킬스위치**: 원래 아이디어였던
   "외국인/기관 순매수 금액(KRW)"은 무료로 실시간 제공되지 않아 그대로 구현할
   수 없습니다. 대신 실제로 받아올 수 있는 **대장주 가격 등락률**로 같은 목적을
   구현했습니다. 지수는 오르는데(+0.1% 초과) 대장주 평균 수익률이 기준(기본
   -0.3%, 슬라이더 조절 가능) 아래면 "이탈"로 판정하고 진입 강도를 절반
   축소합니다. "수급 이탈"이 아니라 "가격 괴리"로 읽어야 합니다.

3. **③ 1시간 델타·가속도 모니터**: 1시간봉으로 시간당 변동률(델타)과 그
   변화량(가속도)을 장중 내내 롤링으로 계산합니다. 오버나이트 갭은 실제 장중
   움직임이 아니므로 자동으로 제외됩니다. "청산 세탁기", "유동성 훅" 같은
   검증 불가능한 해석은 넣지 않고 실측 수치만 보여줍니다.

4. **④ 세션 요약 리포트**: 새로운 판단 로직이 아니라, 위 3가지와 기존 모델
   결과를 한 장의 텍스트로 요약해서 보여주는 출력 계층입니다.

## v2 추가: (만약) 헤지 없이 보유했다면 — VaR (기대손실률)

나스닥 대시보드의 `unhedged_loss_table` 함수를 그대로 이식했습니다. 젬미나이가
제안한 "일간 변동성 × √h" 방식 대신, 다음 두 가지를 반영합니다.

- **μ(기대수익) 포함**: 방향점수 기반 기대수익을 손실 계산에 반영합니다.
- **누적 vol path 기반**: 오늘 변동성 하나에 √h를 곱하는 대신, GJR-GARCH가
  예측한 h일치 변동성 경로를 그대로 제곱합·누적합니다.

화면에는 1~5영업일 기대손실률, 하락확률, 95%/99% VaR을 표로 보여주고,
"상세 분석" expander에도 같은 값이 함께 저장됩니다. 정규분포·매일 독립
가정의 한계(두꺼운 꼬리 리스크 과소평가 가능성)를 캡션에 명시했습니다.

가짜 데이터로 전체 스크립트를 끝까지 실행해 h가 커질수록 VaR가 실제로
벌어지는 것과 기대손실 부호에 따라 성공/경고 메시지가 올바르게 갈리는 것을
확인했습니다.
